# 生图 eval

- `node eval/run.js two-step --runs 5 --out <name>`：对 `eval/cases/` 下每个 case 各生成 N 张，存到 `eval/out/<name>/`（不进 git）。
- `node eval/grade.js <name>`：视觉模型逐张评分，打印每张的失败项、每个 case 的 full pass 率和各检查项通过率。
- 平均耗时：`jq -s '[.[].seconds]|add/length' eval/out/<name>/<case>-[0-9].json`（一次 describe + 一次生图的总时长）。

一张图 full pass = 每排键数与 `expected.json` 的 `rows` 一致，且所有 checks 都通过。
**每次改 prompt、模型或参数，都用同样的命令跑一遍，和下面的基线比。**

### 失败归类

- **右侧导航区少键（13 张失败里的 12 张）**：Insert/Delete 这一对（Enter 那一排右边）被画丢或错位，最常见是两颗都没了、变成空白机身；也有只丢 Delete、Insert 换成多余的 ↑、或 End/PgDn 被挤掉。describe 步骤在全部 20 次里都正确列出了 Insert、Delete（每排键数 13/16/16/15/13/9），所以是图像模型没按清单画，不是清单错。dracula 用的也是同一种配列（右侧两列导航 + Insert/Delete 在 Enter 排），同样的错。
- **颜色、字符、覆盖原键帽**：两个 Dock77 case 的颜色和字符检查 50/50 全过；已装键帽的原字符没有残留或叠印（10/10）。
- 其他：sparta-1 字母字符偏深红（1 张）；dark-serika-5 机身右下局部纹理变平（与少键同一张）。
